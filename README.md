# NEXUS — личный оперативный центр

Открой `index.html` в браузере. Без Supabase данные сохраняются только в браузере и сайт можно использовать офлайн.

## Возможности

- Недельный календарь с часами с 08:00 до 01:00; задачи можно добавлять, редактировать, удалять и перетаскивать.
- Отметка выполнения задачи и отчёты за неделю или месяц: доля выполненных задач, учтённое время, тренировки и отдельная сводка доходов/расходов.
- Баланс, доходы и расходы с категориями.
- Журнал тренировок с недельной целью.
- Проекты с описанием и цветовой меткой; задачу можно привязать к проекту.
- Раздел «Все данные» для добавления, редактирования и удаления задач, операций, тренировок и проектов.
- Несколько локальных профилей; у каждого свои настройки и записи.
- Синхронизация профилей между устройствами через Supabase Auth и защищённую таблицу с RLS.
- Адаптация для телефона.

## Подключение Supabase

Для локальной работы настройка не нужна. Чтобы включить облачную синхронизацию:

1. Создай проект Supabase.
2. В SQL Editor выполни содержимое файла `supabase/schema.sql`.
3. В настройках проекта открой **Authentication → Providers → Email** и оставь включённым вход по почте. В **Authentication → URL Configuration** укажи адрес опубликованного дашборда как Site URL, чтобы ссылки подтверждения почты возвращали в приложение.
4. В **Project Settings → API Keys** скопируй **Project URL** и **Publishable key**. Для проекта из текущей ссылки Project URL: `https://nchctohbsusctrtojlng.supabase.co` (ссылка на `supabase.com/dashboard/...` — это адрес панели управления, не API).
5. Открой дашборд, нажми значок облака, введи эти два значения и сохрани настройки.
6. Создай аккаунт с почтой и паролем в самом дашборде. На другом устройстве укажи тот же URL и Publishable key и войди в тот же аккаунт.

При первом переносе уже существующих записей дашборд попросит подтверждение. Если локальная и облачная копии расходятся, можно объединить записи, загрузить облачную копию на устройство или явно заменить облачную копию данными этого устройства. Перед заменой локальная копия сохраняется для скачивания.

URL проекта и Publishable key предназначены для клиентского приложения; доступ к записям ограничивают политики RLS. **Не вставляй в сайт или чат Secret key / `service_role` key.** Пароль аккаунта вводится только в окне дашборда.

Схема использует одну строку на аккаунт. Политики разрешают читать и менять эту строку только владельцу аккаунта. Синхронизация выполняется при изменении записи, при возвращении на страницу и периодически во время её открытия.

## Хранение данных

Облачная синхронизация не включается автоматически: до настройки Supabase данные остаются в локальном браузере. Подключение Supabase требует опубликованной страницы с доступом к сети. В дашборде используются Supabase JS v2 и политики Row Level Security.

Документация: [Supabase API keys](https://supabase.com/docs/guides/getting-started/api-keys), [Row Level Security](https://supabase.com/docs/guides/database/postgres/row-level-security).
